The problem

A successful backup job is not the same as evidence that a selected item can be extracted from a restore point. This project turns a recurring manual check into a repeatable sample-export workflow for three Microsoft 365 workloads.

What I built

A PowerShell engine and PySide6 desktop application that discovers organizations and jobs on the local Veeam Backup for Microsoft 365 host, runs selected jobs sequentially, and extracts one eligible sample from each workload in the selected job's latest restore point. Exports stay on the VB365 server; the workflow does not write data back to Microsoft 365.

The tool covers three Microsoft 365 workloads:

  • → Exchange Online — Extracts .msg email files from mailbox backup
  • → OneDrive — Extracts documents from user drive backup
  • → SharePoint Online — Extracts items from site backup

Architecture

The core engine is a PowerShell 7 script (Invoke-VB365OriginalRestoreTest.ps1) using the Veeam Archiver PowerShell module. The PySide6 application adds read-only organization/job discovery, sequential execution, per-organization reports, isolated temporary workspaces, and configurable retention.

Audit & reporting

Each completed run produces a required JSON summary and can also produce TXT, HTML, and PDF reports. Evidence includes timestamps, sampled item details, file sizes, SHA-256 checksums, and workload results. A checksum identifies the exported file; it does not prove that every protected object is recoverable.

Scope and limitations

Version 1.2.4 is intentionally local-server only and validates a sample from each selected workload, not every object in a repository. It was released after isolated-lab validation; the supplied records do not show a customer production deployment. Local VB365 administration rights and protected disk space are required because exported evidence may contain sensitive content.
