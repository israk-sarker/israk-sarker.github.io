Project overview

I built and troubleshot a small virtualized business-style environment to practice the dependencies between storage, virtualization, network services, directory services, shared files, and cloud identity. This was a laboratory build, not a production deployment.

Lab layout

Work completed

  • Installed VMware ESXi 7.0.3 on Dell server hardware and connected QNAP iSCSI storage for virtual machines.
  • Configured Windows Server domain services, DNS, DHCP scopes, and DHCP failover.
  • Recovered directory operations after a domain-controller failure. All five FSMO roles were verified on DC02; the final domain-controller pair was DC02 and DC03.
  • Rebuilt departmental file shares and the DFS namespace/replication configuration on the final server pair.
  • Replaced Entra Connect Sync with Microsoft Entra Cloud Sync. Separately moved the custom domain from federated to managed authentication during SafeNet sign-in troubleshooting.

Recorded validation

  • After directory resynchronization, the replication summary reported zero failures across five naming contexts in both directions.
  • The final FSMO role ownership was checked and found on DC02.
  • A lab client received the configured DHCP settings.
  • Microsoft Entra Cloud Sync was enabled for the intended user scope and synchronization was verified.

Limits and remaining validation

The final DFS target list and failover test evidence were not recorded. The Windows LAPS pilot was configured, but password decryption, managed local-account sign-in, and rotation were not fully validated. A final backup and restore from the newer repository disk was also not recorded. These are limits of the available lab evidence, not claims of production readiness.

The environment relied on one ESXi host and one QNAP NAS, so those remained shared points of failure. The lab records also do not establish an independent immutable backup copy.
